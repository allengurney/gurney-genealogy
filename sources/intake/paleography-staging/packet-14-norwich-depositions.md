## Updated-process feedback

What worked:

- Grid-first review was essential. For deposition pages, it quickly distinguished clean headers from body-only references.
- One band-ladder per image was enough to classify all six images before spending on line strips.
- Manual line strips were useful only where the first band already showed a likely answer-bearing phrase.
- Stopping after one line-strip pass on low-contrast pages kept this packet from turning into repeated visual retry work.

What wasted time:

- 14b, 14c, 14d, and 14e had plausible but low-contrast snippets; each could absorb many crop attempts without materially improving the answer.
- The workflow still encourages visual inspection of every contact sheet, which is token-expensive when several images only need triage status.

Where the tool or skill was unclear:

- The current workflow does not have a formal `triage-only` outcome for pages that confirm a contextual hit but fail to answer the packet's demographic question.
- The tool can generate many useful artifacts, but it does not yet produce an answer-focused packet index. The human/model still spends tokens re-reading grids and sheets.

## Cross-packet token-efficiency lessons

Across Packets 16, 13, and 14, the biggest token cost was not storage or command output; it was visual inspection of many large contact sheets. The changes most likely to reduce token use in future rounds are:

1. Add a packet-level triage table step before detailed transcription. Each image should get one of four statuses after the grid and first band sheet: `answerable`, `partial`, `false-positive`, or `blocked`. Only `answerable` images get line strips.
2. Add a `packet-contact-index` tool command that creates one compact sheet containing only the first-pass bands for every image, with labels and coordinates. That would replace opening six separate contact sheets.
3. Add `manifest-summary --contact-sheets-only` or `--labels` filtering. Reports currently require manual selection from noisy manifest output.
4. Add multi-image `info` and multi-image `grid` commands. This does not save many model tokens by itself, but it simplifies the working rhythm and reduces failed/duplicated command discussion.
5. Add a result-template generator from the staging README packet section. The report structure is repetitive; a prefilled markdown skeleton with image names, questions, and artifact paths would save writing and review tokens.
6. Add a stop-rule to the skill: after one grid, one band sheet, and one focused line-strip pass, mark the image `blocked by image quality` unless the second pass materially improves a named answer.

If only one enhancement is worth doing first, it is the packet-level triage table plus compact first-pass contact index. That would have saved the most token-heavy visual inspection across all three recent packets.
