# research/log/

Chronological session logs. One file per active day, named `YYYY-MM-DD.md`.

## Purpose

The log is a lightweight index into the topical files (`people/`, `places/`, `topics/`), not a dump of session content. Content lives in the topical files; the log anchors *when* something was added and *where to look*.

## Format

Each entry is short. A good entry looks like:

```
## 2026-04-15 — Francis G14 sibling search

Searched Ancestry Norfolk parish collection for siblings of Francis Gurney b. 1581 (East Dereham).

Added:
- people/g14-francis-gurney.md § Records examined — three candidate sibling baptisms
- people/g14-francis-gurney.md § Negative results — no match for Peter (expected)
- topics/two-francis-disambiguation.md — confirmed laceweaver active in same decade

Next: cross-check candidate siblings against Boyd's marriage index.
```

A bad entry — one that accumulates substantive content inline rather than pointing into topical files — is a signal that the content should be moved.

## Why this format

Session-based retrieval ("what did we find last Tuesday?") is occasional; topical retrieval ("what do we know about Francis?") is constant. The log serves the occasional case cheaply; the topical files serve the common case well.
